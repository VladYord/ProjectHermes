Current Implementation Snapshot

Vision.md describes the original Hermes idea correctly: a privacy-first assistant that lets you chat with your own documents. What changed is the delivery model. The early MVP vision used a browser-style Next.js frontend, but the implemented product described in doc/plan is now a Tauri desktop application with a Svelte frontend, a Python FastAPI backend sidecar, and local storage for vectors, sessions, and encrypted settings.

Current status from the plan overview: Phases 0 through 6 are done. That means the desktop shell, backend hardening, chat UI, document manager, settings UI, Tauri integration, and the PyInstaller/Tauri build pipeline are implemented. CI/CD and the GitHub Pages landing site are still future work.

How Hermes Can Be Used

Hermes is not just a demo of RAG plumbing. In its current form it can already be used as a practical local-first knowledge tool in several ways:

  • Personal knowledge assistant — ingest PDFs, markdown notes, text files, code files, and OCR-capable images, then ask questions across them from one chat window
  • Engineering or operations reference app — keep manuals, specs, runbooks, and code snippets in one searchable desktop workspace
  • Model comparison workbench — switch between Ollama, OpenAI, Gemini, and Azure OpenAI from the Settings panel without changing the rest of the app
  • Private desktop AI tool — with Ollama it can run as a mostly local document assistant instead of forcing every request through a browser SaaS flow
  • Reusable backend for editors and assistants — the same knowledge and chat services can be exposed through MCP so tools like VS Code can query Hermes directly

What Tauri Is and What It Does Here

Tauri is a desktop application framework that combines a native Rust shell with a web frontend rendered in the operating system's WebView. In Hermes, Tauri is not the AI layer. It is the desktop host that packages and coordinates the UI and backend.

Why RAG Exists

Concepts only — no tools yet. Build the mental model first.
2–3 days

1.1 How LLMs Work

  • Tokens & context windows — A model cannot read your entire hard drive. It has a fixed context limit (4K–200K tokens). This is why RAG exists at all.
  • Hallucination — Structurally inevitable: the model generates the statistically likely next token, not a verified fact. RAG fixes this by providing verified context.
  • Message structure — Every LLM call is a list: System → Human → Assistant → Human → … This is exactly what HumanMessage, AIMessage in agent.py represent.
  • Temperature — 0 = deterministic (facts); 1 = creative (storytelling).

1.2 What an Embedding Is

A sentence converted to a list of floats (e.g., 384 numbers). Semantically similar texts produce numerically similar vectors. Similarity = cosine of the angle between two vectors.

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("all-MiniLM-L6-v2")
a = model.encode("The cat sat on the mat")
b = model.encode("A cat rested on a rug")
c = model.encode("The stock market fell 3%")

def cosine(x, y): return np.dot(x, y) / (np.linalg.norm(x) * np.linalg.norm(y))

print(cosine(a, b))  # ~0.85 — similar
print(cosine(a, c))  # ~0.12 — dissimilar

1.3 Vector Similarity Search

  • Brute-force dot-product over millions of vectors is too slow
  • HNSW (Hierarchical Navigable Small World) — the graph-based index ChromaDB uses internally for fast Approximate Nearest Neighbor search
  • "Approximate" is fine for RAG — being 5% wrong on retrieval is irrelevant compared to the quality gains
  • In knowledge_service.py you see {"hnsw:space": "cosine"} — this selects cosine similarity as the distance metric
✅

Outcome: You understand why the whole system exists. Every tool you learn next has a clear purpose.

The Data Layer: ChromaDB

The right first tool — simplest persistent vector DB, exactly what Hermes uses.

2.1 Core Concepts

import chromadb

# Persistent — survives process restart (what Hermes uses)
client = chromadb.PersistentClient(path="./data/chromadb")

# Ephemeral — in-memory only, for tests
client = chromadb.EphemeralClient()

# A collection is like a "table" for vectors
collection = client.get_or_create_collection(
    name="my_knowledge",
    metadata={"hnsw:space": "cosine"}
)

2.2 The Four Operations

# ADD
collection.add(
    ids=["chunk_0", "chunk_1"],
    documents=["text of chunk 0", "text of chunk 1"],
    metadatas=[{"source": "file.pdf"}, {"source": "file.pdf"}]
)
# QUERY — semantic search
results = collection.query(query_texts=["what is machine learning?"], n_results=5)
# DELETE — by metadata filter
collection.delete(where={"source": "file.pdf"})
# GET — by id
collection.get(ids=["chunk_0"])

2.3 Embedding Functions + Current Limitation

Hermes uses a _HashEmbeddingFunction (SHA-256 hash → 384 floats) as a no-download fallback. This is the biggest current limitation — hash similarity is not semantic.

⚠️ Phase 8 upgrade: Replace with OllamaEmbeddingFunction(model_name="nomic-embed-text") once Ollama is installed. Same model must be used at ingest time AND query time.

Chunking: The Hidden Skill

Chunking quality is the single biggest factor in RAG answer quality. Most tutorials skip this.
2 days
📄Study in Hermes: hermes/processing/chunking.py · hermes/processing/pipeline.py

3.1 Why Chunking Matters

  • LLMs have context limits — you cannot paste a 300-page book into a prompt
  • A chunk is the atomic unit of retrieval — if the answer spans two chunks neither of which is retrieved, the LLM cannot answer
  • Too large → noisy context, lower similarity scores. Too small → incomplete context, answer cut mid-sentence

3.2 RecursiveCharacterTextSplitter — What Hermes Uses

from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,     # characters per chunk (from config.yaml)
    chunk_overlap=200,   # overlap — preserves context across boundaries
    separators=["\n\n", "\n", ". ", " ", ""]  # tries largest first, falls back
)

The overlap is critical: if an answer straddles a chunk boundary, the 200-character overlap ensures both adjacent chunks contain enough context to be useful individually.

The RAG Pattern End-to-End

Wire all components manually before using LangChain. Seeing it raw makes every abstraction transparent.
3–4 days
📄Study in Hermes: hermes/tools/rag_search.py · hermes/services/knowledge_service.py

4.1 Build RAG Without Any Framework

Write this 40-line script from scratch before reading any Hermes code:

import chromadb, openai

client = chromadb.EphemeralClient()
collection = client.create_collection("test")
collection.add(ids=["1","2"], documents=[
    "Python lists are ordered",
    "Dicts store key-value pairs"
])

# Step 1: Retrieve relevant chunks
results = collection.query(query_texts=["how do I store ordered items?"], n_results=2)
chunks = results["documents"][0]

# Step 2: Build prompt with context
context = "\n\n".join(chunks)
prompt = f"Answer based ONLY on this context:\n\n{context}\n\nQuestion: How do I store ordered items in Python?"

# Step 3: Call LLM
response = openai.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": prompt}]
)
print(response.choices[0].message.content)

4.2 The Retriever–Reader Architecture

Every RAG system has exactly two stages:

┌─────────────┐

5.2 The @tool Decorator

The docstring becomes the tool description the LLM sees. The type hints become the JSON schema.

from langchain_core.tools import tool

def create_rag_search_tool(knowledge):
    # Factory — closes over knowledge service instance
    @tool
    def search_knowledge_base(query: str, top_k: int = 5) -> str:
        """Search the local knowledge base for information relevant to the query.
        Returns the most relevant text passages from ingested documents."""
        results = knowledge.search(query, top_k)
        return format_results(results)
    return search_knowledge_base

5.3 create_agent / LangGraph — The Agent Loop

from langchain.agents import create_agent

graph = create_agent(model=llm, tools=[rag_tool], system_prompt="You are Hermes...")

# Non-streaming
result = await graph.ainvoke({"messages": [HumanMessage(content="...")]})
answer = result["messages"][-1].content

# Streaming — yields events token by token
async for event in graph.astream_events({"messages": [...]}, version="v2"):
    if event["event"] == "on_chat_model_stream":
        token = event["data"]["chunk"].content
        print(token, end="", flush=True)

The ReAct loop: LLM sees messages + tool schemas → decides to call tool or answer → if tool: LangGraph executes it, result appended as ToolMessage → LLM sees updated messages → final answer.

⚠️ LangChain version warning: This project uses LangChain ≥0.3 with create_agent (LangGraph-based). Older tutorials use the deprecated AgentExecutor. Filter out any tutorial using initialize_agent() or AgentExecutor.

FastAPI

The serving layer. Endpoints are thin wrappers — learn the core logic first.
3–4 days
📄Study in Hermes: hermes/server.py · hermes/middleware/auth.py

6.1 Lifespan Events

from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # STARTUP — runs before first request
    _knowledge = KnowledgeService()
    _chat_service = ChatService(_knowledge, ...)
    yield
    # SHUTDOWN — cleanup here

app = FastAPI(lifespan=lifespan)

Why not at module level? Avoids circular imports — config.yaml must load before any service reads it.

6.2 SSE Streaming

from fastapi.responses import StreamingResponse

async def token_generator():
    async for token in chat_service.chat_stream(message):
        yield f"data: {json.dumps({'token': token})}\n\n"
    yield "data: [DONE]\n\n"

return StreamingResponse(token_generator(), media_type="text/event-stream")

SSE format: each event is data: <payload>\n\n (double newline required). The browser EventSource API reads this natively.

auth.enabled=false → all pass through | localhost → always passes | remote → requires X-API-Key header matching config.yaml value → 401 if wrong.

MCP Protocol

VS Code Copilot integration — just a different transport for the same core logic.
2–3 days
📄Study in Hermes: hermes/mcp_server.py

9.1 What MCP Is

  • Model Context Protocol — open standard (Anthropic) for connecting tools to AI assistants
  • Three primitives: Tools (functions LLM can call), Resources (data it can read), Prompts (templates). Hermes uses only Tools.
  • Same concept as LangChain's @tool — but MCP is a transport-level standard, not a library-level abstraction

9.2 Transport: stdio

VS Code spawns Hermes as a child process. All communication goes over stdin/stdout as JSON-RPC 2.0. No port, no server management.

python -m hermes --mcp   # VS Code runs this automatically

9.3 FastMCP

from mcp.server import FastMCP

mcp = FastMCP(name="hermes", instructions="...")

@mcp.tool()
def search_knowledge(query: str, top_k: int = 5) -> str:
    """Search the local knowledge base — docstring becomes tool description."""
    results = knowledge.search(query, top_k=top_k)
    return format_results(results)

@mcp.tool()
async def ask_hermes(question: str) -> str:
    """Full RAG pipeline — retrieval + LLM reasoning."""
    response = await chat_service.chat(message=question)
    return response.answer

10.2 Re-Ranking

Vector similarity is a recall measure. After retrieving top-20 chunks by vector similarity, run a cross-encoder re-ranker to re-score and keep only the top-3 most precisely relevant.

from sentence_transformers import CrossEncoder
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
scores = reranker.predict([(question, chunk) for chunk in chunks])
ranked = sorted(zip(chunks, scores), key=lambda x: x[1], reverse=True)
top_chunks = [c for c, _ in ranked[:3]]

10.3 Hybrid Search (BM25 + Vector)

BM25 (keyword) catches exact term matches — IDs, proper names, technical codes. Vector catches semantic matches. Combined, they handle every query type.

10.4 Query Expansion

Short user questions often miss relevant chunks. Have the LLM rewrite the question into 3 alternative phrasings before searching. Merge and deduplicate all results.

10.5 Contextual Chunking

Problem: retrieved chunks lose context when read in isolation. Solution: prepend a short document/section summary to every chunk before storing it in ChromaDB.

10.6 Evaluation with RAGAS

pip install ragas

    questions=test_questions,
    answers=model_answers,

Step-by-step: add new tools, call external APIs, add web search, and route different tools to different LLMs.

11.1 How the Agent Uses Tools

Before adding anything, understand the flow. The LangGraph agent alternates between two nodes:

User message
    │
    ▼
HermesAgent (LangGraph StateGraph)
    │
    ├── model node  ──► LLM decides: answer directly OR call a tool
    │                        │
    │                        ▼
    └── tools node  ──► executes the chosen @tool, result added to messages
         │
         ▼
    model node again ──► LLM reads tool result, decides next step or final answer

The LLM sees only the tool name + docstring to decide which to call. The docstring is the instruction — write it carefully.

11.2 Step-by-Step: Adding a New Tool

Example: A tool that calls an internal REST API to look up a component by part number.

Step 1 — Create the tool file at hermes/tools/bosch_api_search.py:

"""Tool: look up a Bosch component via the internal parts API."""
from __future__ import annotations
from langchain_core.tools import tool

@tool
def bosch_component_lookup(part_number: str) -> str:
    """Look up a Bosch component by part number using the internal parts API.

    Returns component name, description, status, and compatible systems.
    Use this when the user asks about a specific part number or component.
    """
    import httpx
    url = f"https://internal-api.bosch.com/parts/{part_number}"
    r = httpx.get(url, headers={"Authorization": "Bearer ..."}, timeout=10)
    if r.status_code == 404:
        return f"Part number {part_number} not found."
    if r.status_code != 200:
        return f"API error {r.status_code}: {r.text[:200]}"
    data = r.json()
    return (
        f"Part: {data['name']}\nDescription: {data['description']}\n"
        f"Status: {data['status']}\nCompatible with: {', '.join(data['compatible_systems'])}"
    )
💡 Three rules for tool functions: (1) always return a str, (2) catch all exceptions and return an error string instead, (3) make the docstring precise about when to use this tool — not what it does.

Step 2 — Register the tool in hermes/services/chat_service.py:

from hermes.tools.rag_search import build_rag_search_tool
from hermes.tools.bosch_api_search import bosch_component_lookup

def _get_agent(self, provider: str | None) -> HermesAgent:
    ...
    rag_tool = build_rag_search_tool(self._knowledge)
    agent = HermesAgent(llm=llm, tools=[rag_tool, bosch_component_lookup])  # ← added

Step 3 — Expose via MCP (optional) in hermes/mcp_server.py:

@mcp.tool()
def lookup_component(part_number: str) -> str:
    """Look up a Bosch component by part number."""
    from hermes.tools.bosch_api_search import bosch_component_lookup
    return bosch_component_lookup.invoke({"part_number": part_number})

Step 4 — Test it in isolation:

11.4 LLM Orchestration — Different Models per Tool

Different tasks justify different models. Web search summarization needs speed; final answer synthesis needs reasoning power.

Approach 1 — Tool-level LLM selection (simplest): call a specific provider directly inside the tool.

from langchain_core.tools import tool
from hermes.core.llm_router import LLMRouter

@tool
def web_search_and_summarize(query: str) -> str:
    """Search the web and return a summarized answer. Use for current events
    or information not in the local knowledge base."""
    import httpx
    r = httpx.get("https://api.duckduckgo.com/",
                  params={"q": query, "format": "json"}, timeout=10)
    raw = r.json().get("AbstractText", "no results")

    # Summarize with a FAST/CHEAP model
    fast_llm = LLMRouter().get_provider("bosch_llm_farm")   # gpt-4o-mini
    response = fast_llm.invoke(f"Summarize in 3 sentences:\n{raw}")
    return response.content

Approach 2 — LiteLLM proxy gives a unified OpenAI-compatible interface to 100+ models with routing rules:

pip install litellm

model_list:
  - model_name: fast

      model: azure/gpt-4o

# In your code — identical interface regardless of backend

response = litellm.completion(model="fast",     messages=[...])

Approach 3 — Native Hermes config routing: extend config.yaml with task-specific provider keys and read them inside tools via get_config().

11.5 Complete Example — Two-Agent Pipeline

User: "What is the latest EU regulation on e-bike motor power?"
         │
         ├─► RAG search ── fast LLM ──► ChromaDB → internal spec excerpts
         │
         ├─► Web search ── fast LLM ──► DuckDuckGo → current regulation news
         │
         ▼
    Synthesizer ── powerful LLM ──► combines both results → final answer
from langchain_core.tools import tool
from hermes.core.llm_router import LLMRouter

def build_dual_search_tool(knowledge_service):
    fast_llm = LLMRouter().get_provider("bosch_llm_farm")

    @tool
    def dual_search(query: str) -> str:
        """Search both local documents AND the web, then synthesize a combined answer.
        Use when the question may need both internal knowledge and current external info."""
        from hermes.tools.rag_search import build_rag_search_tool
        from langchain_community.tools import DuckDuckGoSearchRun

        local = build_rag_search_tool(knowledge_service).invoke({"query": query, "top_k": 3})
        web   = DuckDuckGoSearchRun().invoke(query)

        prompt = (f"Combine these sources to answer: \"{query}\"\n\n"
                  f"LOCAL:\n{local}\n\nWEB:\n{web}")
        return fast_llm.invoke(prompt).content

    return dual_search

11.7 Key Concepts

📌 Tool docstring = LLM instruction. The LLM reads only the name and docstring to decide whether to call a tool. If two tools have similar descriptions, the LLM will pick the wrong one. Make descriptions distinct and precise about when each should be used.
📌 Tools must never raise exceptions. If a tool throws, the entire agent run fails. Always wrap external calls in try/except and return a descriptive error string.
💡 Cost rule of thumb: gpt-4o-mini costs ~20× less than gpt-4o per token. Use the fast model for web result summarization, classification, and data extraction. Use the powerful model only for complex reasoning over long context and final answer synthesis.
